# Fix 502 on www.katariastoneworld.com

Login/signup work on **`api.katariastoneworld.com`** — that is the **backend** service.

`www.katariastoneworld.com` is a **different Railway service** (nginx gateway + React UI).
A 502 on `/health` or `/inventory/` means Railway cannot reach the gateway container.

## Quick proof

```bash
curl.exe -sI https://api.katariastoneworld.com/actuator/health
# -> 200 (API is fine)

curl.exe -sI https://www.katariastoneworld.com/health
# -> 502 (gateway broken — /health does not call the API)
```

## Fix in Railway (gateway / inventory service)

### Step 1 — Open the correct service

Railway project → service that builds from **`kataristoneworldinventory`** repo
with Dockerfile **`deploy/gateway/Dockerfile`**.

Do **not** use the API/backend service.

### Step 2 — Networking → Target Port

1. Settings → **Networking** → **Public Networking**
2. Copy the current `*.up.railway.app` URL
3. Set **Target Port** to **Auto** (or `$PORT`)
4. If you set a number manually, it **must** match deploy logs:
   ```text
   [gateway] PORT=8080 (Railway Target Port must match this)
   ```

### Step 3 — Variables

Delete these if present (empty values break deploy):

- `PORT` (empty)
- `BACKEND_URL` (empty)

Keep or add:

```env
BACKEND_URL=https://api.katariastoneworld.com
```

Build variable:

```env
REACT_APP_API_URL=https://www.katariastoneworld.com
```

### Step 4 — Custom domain

1. Remove `www.katariastoneworld.com` from any other Railway service
2. Add it only on the **gateway** service
3. Update DNS CNAME to the hostname Railway shows (not an old `*.up.railway.app` that returns 404)

Current DNS check (run locally):

```bash
nslookup www.katariastoneworld.com
```

If the CNAME target returns **404 Application not found**, the domain points to a **deleted** Railway service. Re-add the domain on the live gateway service and update DNS.

### Step 5 — Redeploy and test in order

```bash
# 1) Railway default URL first (from Networking tab)
curl.exe -s https://YOUR-SERVICE.up.railway.app/health
# expect: ok

curl.exe -sI https://YOUR-SERVICE.up.railway.app/inventory/
# expect: 200

# 2) Then custom domain
curl.exe -s https://www.katariastoneworld.com/health
curl.exe -sI https://www.katariastoneworld.com/inventory/
```

### Step 6 — Deploy logs

Successful deploy should show:

```text
[gateway] PORT=8080 (Railway Target Port must match this)
[gateway] self-test passed: http://127.0.0.1:8080/health -> ok
```

If deploy **fails** after push, read the log — the self-test caught a port/bind problem before Railway marked it healthy.

| URL | What it serves |
|-----|----------------|
| `https://www.katariastoneworld.com/` | Redirect → `/inventory/` |
